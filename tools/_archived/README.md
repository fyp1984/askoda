# 已归档脚本

## TEI / embedding 排查脚本（2026-10-06 归档）

**归档原因**：跨机迁移 embedding 的尝试已停止（实测本机 TEI 仅占 2.1GiB/15.66GiB、
CPU 1.77%，不是资源瓶颈；迁移收益远小于成本）。

**保留价值**：后期若再遇到 TEI 启动异常、要做跨主机 embedding、或要复现本轮诊断过程，可直接复用。

| 脚本 | 用途 | 本轮结论 |
|---|---|---|
| `diagnose_tei.sh` | 第一版诊断：服务状态 / 端口 / 启动方式 / 模型完整性 / 资源 / 20 轮稳定性 | **缺陷**：未打印模型目录顶层文件，导致三轮才看出模型格式问题 |
| `diagnose_tei2.sh` | 第二版：补上「模型格式判定」（ONNX vs PyTorch）+ 崩溃真相 + 退出码 | 定位到真病根：挂的是 PyTorch 版模型，无 ONNX 文件 |
| `fix_tei.sh` | 修复：加 pooling cls / workers 2 / batch 8 / 内存限 8g / unless-stopped | 参数全对仍 12/30 失败 —— 证明问题不在参数 |
| `fix_tei_model.sh` | 一步到位换 ONNX 模型（scp / download / apply 三模式） | 未执行（迁移已停止） |

**本轮最重要教训（三条）**：
1. **参数调优救不了模型格式不对** —— 排查应先看输入物料，再调运行参数。
2. **诊断脚本要打印「物料清单」而不只是「状态」** —— 第一版漏了这项，是拖到第三轮的主因。
3. **`RestartCount` 是区分「僵死」与「崩溃」的决定性指标** —— 第一轮为 0（僵死），第二轮变 1（真崩过）。

**复用提示**：`fix_tei_model.sh --scp` 可把本机 `.models/bge-m3`（ONNX 版，11 个文件）传到任意 TEI 主机。
