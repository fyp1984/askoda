# 表结构与颗粒度说明 · 零售会员域

本文件说明零售会员域（数据集 B）八张核心表的颗粒度、关键字段与关联路径。
**颗粒度**回答的是"一行数据代表什么"，这是需求分析阶段最先要确认的事情之一。

## 一、表清单

| 表名 | 业务含义 | 颗粒度（一行代表什么） | 主键 |
|---|---|---|---|
| `dim_store` | 门店维表 | 一家门店 | `store_id` |
| `dim_member` | 会员维表 | 一名会员 | `member_id` |
| `dwd_order_di` | 订单明细表 | 一笔订单 | `order_id` |
| `dwd_order_detail_di` | 订单明细扩展表 | 一个订单行（订单中一个 SKU） | `detail_id` |
| `dws_store_daily_agg` | 门店日汇总表 | 一家门店的一天 | `stat_date` + `store_id` |
| `ads_coupon_order_di` | 券核销记录表 | 一次券核销 | `coupon_order_id` |
| `ads_member_grade_change_wi` | 会员等级异动表 | 一名会员一个月的一次等级异动 | `change_id` |
| `ads_member_repurchase_di` | 会员复购汇总表 | 一名会员一个月一条 | `member_id` + `stat_month` |

> **颗粒度踩坑提醒**：`dwd_order_di` 一行是一笔订单，`dwd_order_detail_di` 一行是一个订单行。
> 一笔订单可能对应多个订单行，因此**直接对明细表求和会不可逆地放大订单笔数**。
> 需要订单数时用订单表，需要商品/品类维度的销售额时用明细表，两者不能混。

## 二、关键字段说明

### dim_store（门店维表）

| 字段 | 说明 |
|---|---|
| `store_id` | 门店 ID |
| `store_name` | 门店名称 |
| `region_name` | 所属大区；枚举：华东大区 / 华北大区 / 华南大区 |
| `store_type` | 门店类型；枚举：直营 / 加盟 |
| `open_date` | 开业日期 |

### dim_member（会员维表）

| 字段 | 说明 |
|---|---|
| `member_id` | 会员 ID |
| `member_name` | 会员姓名 |
| `grade` | 会员等级；枚举：普通 / 银卡 / 金卡 / 钻石 |
| `member_status` | 会员状态；枚举：活跃 / 沉默 / 流失 |
| `register_date` | 注册日期 |
| `store_id` | 归属门店 |

> 该表另有 `member_phone`、`id_card` 两个字段，属于受控字段，详见《数据安全与敏感字段管理办法》。

### dwd_order_di（订单明细表）

| 字段 | 说明 |
|---|---|
| `order_id` | 订单 ID |
| `member_id` | 会员 ID |
| `store_id` | 门店 ID |
| `pay_amount` | 实付金额（元） |
| `order_date` | **业务日期**，分析一律用此字段 |
| `order_status` | 订单状态；枚举：已完成 / 已退款 |

> 该表另有 `load_time` 字段（数据装载时间），属于技术字段，不用于业务时间口径。

### dwd_order_detail_di（订单明细扩展表）

| 字段 | 说明 |
|---|---|
| `detail_id` | 明细行 ID |
| `order_id` | 所属订单 ID |
| `store_id` | 门店 ID |
| `sku_id` | SKU 编码 |
| `category_name` | 品类名（维度退化列，可直接分组，无需 JOIN） |
| `quantity` | 购买数量 |
| `unit_price` | 成交单价（元） |
| `sales_amount` | 销售金额（元）= 数量 × 单价 |

品类枚举：美妆 / 个护 / 食品 / 服饰 / 家居 / 数码。

### dws_store_daily_agg（门店日汇总表）

| 字段 | 说明 |
|---|---|
| `stat_date` | 统计日期 |
| `store_id` | 门店 ID |
| `sales_amount` | 当日销售额（元） |
| `order_cnt` | 当日订单数 |
| `member_cnt` | 当日下单会员数 |
| `area_sqm` | 门店经营面积（平方米），坪效计算的分母 |
| `day_type` | 日期类型；枚举：工作日 / 周末 / 节假日 |

### ads_coupon_order_di（券核销记录表）

字段：核销记录 ID、会员 ID、券种、券面额、用券订单 GMV、核销日期。
券种枚举：满减券 / 折扣券 / 新人券。相关口径当前为"待上架"状态。

### ads_member_grade_change_wi（会员等级异动表）

字段：异动记录 ID、会员 ID、异动月份（月粒度）、异动类型（升级 / 降级）。

### ads_member_repurchase_di（会员复购汇总表）

| 字段 | 说明 |
|---|---|
| `member_id` | 会员 ID |
| `store_id` | 归属门店 |
| `stat_month` | 统计月份（月粒度，存当月 1 日） |
| `repurchase_flag` | 当月是否复购，0/1 |
| `order_cnt` | 当月订单数 |

## 三、关联路径

已建模的关联关系如下，未列出的表间**不存在**关联，不能假设可以 JOIN：

- 订单 → 会员：`dwd_order_di.member_id = dim_member.member_id`
- 订单 → 门店：`dwd_order_di.store_id = dim_store.store_id`
- 明细 → 订单：`dwd_order_detail_di.order_id = dwd_order_di.order_id`
- 明细 → 门店：`dwd_order_detail_di.store_id = dim_store.store_id`
- 日汇总 → 门店：`dws_store_daily_agg.store_id = dim_store.store_id`
- 会员 → 门店：`dim_member.store_id = dim_store.store_id`
- 券核销 → 会员：`ads_coupon_order_di.member_id = dim_member.member_id`
- 等级异动 → 会员：`ads_member_grade_change_wi.member_id = dim_member.member_id`
- 复购汇总 → 会员：`ads_member_repurchase_di.member_id = dim_member.member_id`
- 复购汇总 → 门店：`ads_member_repurchase_di.store_id = dim_store.store_id`

**券核销表与订单表之间没有建模关联**。如果需求要"把用券订单和销售明细对上"，
这是一个需要先确认关联主键的口径问题，不能默认两表可直接 JOIN。
